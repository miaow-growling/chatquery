Rust 驱动 · 毫秒级冷启 · 内存平稳有界

采用 Rust 编写的无 GC 单二进制内核与 Tauri 架构，启动耗时仅需约 50ms。通过 ADR-006 惰性加载与 LRU 有界缓存，桌面端常驻约 60~120MB（终端仅 ~20MB），连接数增加时内存依然平稳，告别 Java/Electron 动辄 GB 级的内存膨胀。

AI 原生智能体 · 跨会话 @ 深度引用

会话持久化与上下文感知，词首输入 @ 即可把正在编辑的 SQL、查询结果或历史对话注入 Prompt。内置 ExecutionBlock 步骤折叠与 SQL 前置可审计机制。

MySQL & Redis 双引擎 · 多环境拓扑

FAQ

常见问题解答

关于安全性、环境支持与大模型接入的疑问解答。

ChatQuery 支持哪些数据库和版本？ +
ChatQuery 原生支持 MySQL 5.7、8.0、8.4 以及兼容协议的 MariaDB、Tidb 等；Redis 全面支持 4.x 到 7.2+ 及最新 8.0，覆盖 String、Hash、List、Set、ZSet 等所有原生数据结构，提供 TTL 可视化调整与 Raw / Formatted JSON / Hex 视图。
使用 AI 对话查询时，我的业务敏感数据安全吗？ +
非常安全。ChatQuery 秉持本地优先（Local-First）原则：所有连接配置与密码均通过本地 AES-256-GCM 高强度加密，网络连接直接直连数据库。在向大模型发起对话时，仅将必要的 Schema 表结构（可开启脱敏）或用户明确 @ 引用的上下文发送给您配置的 API 端点，绝不会在任何外部云端持久化您的真实数据。
什么是 C3 宪法级防全表扫描？ +
这是 ChatQuery 内置的生产防灾护栏机制：对于缺少主键或索引过滤的大表扫描、无 WHERE 条件的 UPDATE/DELETE，客户端会主动预警并拦截。AI Agent 在写后验证时也严格禁止全表扫描拉取，强制通过执行返回状态或主键单条精确回查，避免大表性能灾难。
可以在无桌面的 Linux 服务器或 SSH 跳板机上运行吗？ +
完全可以。ChatQuery 基于模块化架构构建，除桌面 GUI 之外，同一个二进制程序支持 chatquery --tui 极客交互模式，在 SSH 会话中即开即用，无需任何 X11 或图形界面支持。
如何配置我自己的大模型 API Key？ +
点击界面左上角的设置图标（⚙），进入 LLM 模型设置页面。您可以填入任意支持 OpenAI 兼容格式的 API 基础地址（Base URL）和您的专属 Key（如 DeepSeek-V3、GPT-4o、Claude 3.5 Sonnet、Qwen 或本地部署的 Ollama），完全由您自主掌控。
