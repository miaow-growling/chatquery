## 修复 BUG：`Table 'kf_ai.kf_ai' doesn't exist`（Phase 11 后续，用户双击表报此错）
- 根因：`browse` 拼 SQL 用**空格**分隔库名与表名 → `SELECT * FROM \`kf_ai\` \`kf_ai\``。MySQL 把第一个 `\`kf_ai\`` 当成当前库里的**表名**（`kf_ai` 恰是连接默认库），第二个当别名 → 报 `Table 'kf_ai.kf_ai' doesn't exist`。**与点的真实表名无关**，故双击任何表都报同一错。
- 修复：`src/db/mysql.rs` 改为**点号**连接 `` `db`.`tbl` ``；并把拼接抽成 `qualified_table(db, tbl)` 方便单测。
- 加回归单测：`qualified_table_uses_dot_not_space`（断言 `kf_ai`+`orders`→`` `kf_ai`.`orders` ``）、`quote_ident_strips_backticks`。`cargo test --lib` 16 项全绿（含 3 个 mysql 新增）。

## 修复 BUG：双击表白屏（用户"双击表白屏了"）
- 根因：**serde 枚举 tag 大小写不匹配**。Rust `QueryOutput` 用 `#[serde(tag="kind")]` 但变体名 `Table`/`Redis` 默认序列化为 `"Table"`/`"Redis"`（大写 T/R）；前端 `renderResult` 判断 `r.kind === "table"`（小写）。
  - 报错路径（之前的 1146）反而正常：因为错误对象由**前端自己构造** `{kind:"redis",...}`（小写），匹配得上 → 能显示。
  - 成功路径：后端返回 `{kind:"Table",columns,rows,...}`（大写）→ `r.kind==="table"` 为 false → 落到 `redis` 分支执行 `r.lines.map(...)`，而 Table 结果无 `lines` 字段 → `undefined.map` 抛异常 → React 整树卸载 = **白屏**。
- 修复：`src-tauri/src/commands.rs` 的 `QueryOutput` 加 `rename_all = "lowercase"`（`#[serde(tag="kind", rename_all="lowercase")]`）→ wire 变 `table`/`redis`。`DbType` 早已有该属性（连接类型小写无此问题）。
- 防御：**新增 `frontend/src/ErrorBoundary.tsx`** 包住 `<App/>`，今后任何渲染期异常显示可读错误面板（而非静默白屏）；`main.tsx` 接入；`style.css` 加 `.crash` 样式。
- 验证：cargo check(src-tauri) ✅；npm run build ✅（TS 零错）；重启 tauri dev（任务 WBBUaI，重编译 8s 后原生窗口弹出运行）。
- 教训：Rust→前端 的枚举/字符串契约，**务必显式 `rename_all`/显式 tag 值对齐前端判断**；并加 ErrorBoundary 兜住渲染崩溃，避免白屏掩盖根因。
