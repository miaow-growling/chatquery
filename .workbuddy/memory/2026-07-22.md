# 2026-07-22

## 本地数据库终端工具（Navicat 替代品）— 架构设计
- 用户需求：本地终端程序，支持 MySQL + Redis 查询；资源占用小；接入 LLM 对话查询 + MCP 工具。
- 已确认决策：Rust 单二进制 / 云端 OpenAI 兼容流式 API / 完整交互式 TUI(ratatui) / MCP 走 stdio 子进程按需拉起。
- 产出：`ARCHITECTURE.md`（模块化单体 + 5 份 ADR + 资源预算 + Phase1-5 路线图）、`overview.md`。
- 核心权衡：LLM 算力上云 + MCP 进程隔离 + 原生编译，把主程序 RSS 压到 <30MB；代价是 LLM 需网络/Key 且 SQL 会上云（需脱敏选项）。
- 下一步：Phase 1 脚手架（Rust + tokio + ratatui + SQLite + MySQL 适配器），待用户确认后开始实现。
- 新增 ADR-006：惰性加载 + 有界内存。用户指出 Navicat 类工具"连接即全量预载导致连接越多越卡"的反模式；本工具改为惰性元数据 + 有界结果集(LIMIT/游标分页/流式fetch) + 受限连接池(TTL回收) + LRU 元数据缓存 + Redis 用 SCAN 而非 KEYS。内存随连接数近似常数。
- **Phase 1 已实现并编译通过（零警告）**：Rust 工程 + ratatui 三面板 TUI + `chatquery add` 落库连接（SQLite 验证可用）+ MySQL 流式有界查询(200行)。debug 二进制 15MB。
- 踩坑结论（重要，可复用）：① ratatui 0.29 / crossterm 0.28 / tui-textarea 0.7 必须对齐版本，否则 `Widget` trait 跨版本不匹配编译失败；② sqlx 必须 `default-features=false` 仅开 `runtime-tokio,mysql,chrono`，否则默认特性编译 OOM(exit 137)；③ 构建用 `CARGO_BUILD_JOBS=2 RUSTFLAGS="-C codegen-units=1"` 避 OOM。

## Phase 2 — Redis 适配器（已完成，2026-07-22）
- 新增依赖：`redis = "0.27"`（features=["tokio-comp"]）；error.rs 加 `AppError::Redis`。
- redis.rs：连接(AUTH/SELECT)、通用命令执行、`SCAN` 游标遍历(上限 500 键, 硬上限 5000 轮防死循环)、拦截 `KEYS` 返回提示、Value 扁平化为行。`redis::Value` 在 0.27 变体改名：Data→BulkString、Status→SimpleString、Bulk→Array。
- `redis::Cmd::query_async` 只有**一个**泛型参数（返回类型 T），连接是 `con: &mut impl ConnectionLike`，不能写 `query_async::<_, T>(&mut conn)` 的 turbofish（否则 `_` 被当连接类型报 ConnectionLike 不满足）；正确：`.query_async::<T>(&mut conn)`。
- app.rs 引入 `DisplayResult` 联合枚举（Table/Redis），`run_query` 按 DbType 分派；ui.rs 用 List 渲染 Redis 结果（带 `$ <cmd>` 回显 + 截断提示）；main.rs 状态栏显示 note。
- 验证：本地 redis-server(6390)，`cargo test smoke_redis` 真实验证 SET/GET/HGETALL/SCAN/KEYS拒绝 全过。测试 `#[cfg(test)]` 且 redis 不可用时自动跳过。
- 构建：debug 15MB，release 实测 **2.1MB**（opt-level=z + lto + strip + codegen-units=1，未 OOM）。
- 文档：ARCHITECTURE.md 加 ADR-007(DisplayResult 联合) + 更新进度/体积/redis 踩坑；overview.md 同步。已知限制：Redis 命令行不支持引号内空格。

## Phase 3 + 模块化重构（已完成，2026-07-22）
- 用户要求"按模块拆分目录，稍微工程化一些"。按 ADR-008 把 `src/` 从平铺重构为 bounded-context 模块：`config.rs`(LLM env 配置) / `model.rs`(跨模块类型 DisplayResult/BackendMsg/ChatMessage) / `store/`(SQLite, 原 storage.rs) / `db/`(connection/mysql/redis) / `llm/`(client/session/tools) / `tui/`(app/ui/event)。依赖单向：tui→{model,db,llm}; llm→{db,model}; db→{store,model}。
- LLM 实现：`llm/client.rs` 流式调用 OpenAI 兼容 `/chat/completions`（SSE 解析，`parse_sse` 有单测）；`llm/tools.rs` 的 `execute_query` 工具（按连接名查 ConnectionConfig 分派 mysql/redis 适配器）；`llm/session.rs` `run_turn` 工具循环（≤5 轮 tool 迭代，结果回灌续答）。配置走 env `CHATQUERY_LLM_*`(BASE_URL/API_KEY/MODEL)，**不落盘**(ADR-004)。
- TUI：新增 `Focus::Chat`，`Tab` 在 Connections→Editor→Chat 循环；chat_textarea + chat 历史 + chat_streaming 流式上屏；BackendMsg 加 ChatToken/ChatTool/ChatDone 变体。模型用原生 function calling（tool_calls 增量累积）。
- 编译零警告；release 实测 **3.0MB**（加入 reqwest/rustls）。`cargo test` 全绿（parse_sse + smoke_redis）。
- 新踩坑（已写入 ARCHITECTURE.md 第9节）：① reqwest 0.12 的 `tokio` **不是可列特性**（异步运行时硬编码依赖），用 `default-features=false, features=["json","stream","rustls-tls"]`；② `tokio::spawn` 的 future 必须 Send，跨 await 持 `&mut dyn FnMut(&str)` 破坏 Send → 改为 `&mut (dyn FnMut(&str) + Send)`。
- 已知限制：Chat 转录不滚动；LLM 需联网+Key（沙箱无 TTY/Key 未端到端验证）；Redis 引号内空格仍不支持。
- 下一步：Phase 4 MCPHost(stdio 子进程 + 工具注册到 LLM)。

## Phase 4 — MCP Host（已完成，2026-07-22）
- 按 ADR-009 新增 `src/mcp/{mod,transport,host}.rs`：MCP server 作为**独立子进程**（stdio 传输，裸 JSON-RPC 2.0）。`transport.rs` 用 `std::process::Command` spawn + 后台线程读 stdout 行 → mpsc 通道，`recv_response(id, timeout)` 跳过无 id 的 notification 匹配指定 id。`host.rs` 实现 `initialize`(id=1)→`notifications/initialized`→`tools/list`(id=2) 握手、`tools/call`(id=3)、`McpHostManager`(tokio::Mutex<HashMap> 懒连接 + 崩溃跳过)。
- 零新增依赖（纯 std::process + serde_json），release 仅 +0.1MB → **3.1MB**。
- 工具命名空间 `mcp__<server>__<tool>`（decode 用 splitn(2,"__")）；`config.rs` 加 `McpServerConfig` + `load_mcp_servers()`（env `CHATQUERY_MCP_SERVERS` JSON 数组，**不落盘**）。`llm/tools.rs` exec_tool 加 mcp 路由（Option<&McpHostManager>），`run_turn` 合并 mcp 工具 schema；`tui/app.rs` 加载 manager(Arc) 传 run_turn，状态栏显示 `mcp=N`。
- 验证：`tests/mcp_echo_server.py` 裸 JSON-RPC fixture（python3，无 SDK）；`mcp_handshake_against_fixture` 集成测试真实 spawn+握手+list+call 全过。`cargo test` 5 项全绿。
- error.rs 加 `AppError::Json(#[from] serde_json::Error)`（transport 用）。
- 已知限制（Phase 4）：子进程调用是同步 IO（持 tokio Mutex 期间，毫秒级，并发串行化）；未实现空闲回收/自动重连（进程驻留到退出或崩溃后本次会话不可用）。
- 下一步：Phase 5 打磨（Chat 转录滚动、连接配置加密/keychain、Redis 引号解析、结果导出、主题）。

## Phase 5 — 打磨（已完成，2026-07-22）
- 做 4 项：① Redis 引号解析 ② 连接配置加密(ADR-010) ③ 结果/转录滚动 ④ 结果导出。主题留后续。
- 加密：新增 `src/crypto.rs`（AES-256-GCM + getrandom + base64），密钥独立存 `~/.config/chatquery/key`(0600)。`store/mod.rs` 持 `key` 字段，`upsert_connection` 加密整条 JSON，`load_connections` 解密；**解密失败回退明文 + 加载时把旧明文记录就地重写加密**（首次加载后 DB 全加密）。威胁模型：只防被动泄露（泄露 app.db 无密钥解不开），不防已获账户的攻击者；彻底隔离需 OS keychain（未来选项，不引跨平台 keychain 依赖保持轻量）。
- Redis 引号：`db/redis.rs` 新增 `tokenize`（单/双引号 + 反斜杠转义），替换 `split_whitespace`；`SET k "a b"` 正确解析。含单测。
- 滚动：`tui/app.rs` 加 `chat_scroll/chat_follow/result_scroll/result_follow`；`PgUp/PgDn` 滚动、`End` 回底；`Ctrl+E` 导出当前结果（mysql::to_csv → CSV 带字段转义，Redis → TXT）。`ui.rs` 用切片窗口渲染 Table/List（因 ratatui 0.29 移除 `Table::scroll`/`List::scroll` 构建器，改 stateful 或切片）。`Paragraph::scroll((y,0))` 仍可用（转录）。
- 验证：编译零警告；`cargo test` 7 项全绿（新增 tokenize_respects_quotes / to_csv_quotes_special_fields + smoke_redis/mcp/sse 回归）；release **3.2MB**（+0.1MB）。加密端到端验证：add 带特征密码后 grep app.db 无任何明文 JSON/`password`/密码子串。
- 文档：ARCHITECTURE.md 加 ADR-010 + Phase5 进度/已知限制刷新 + ratatui0.29 滚动踩坑；overview.md 同步。
