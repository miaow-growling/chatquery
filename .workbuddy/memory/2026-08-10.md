# 2026-08-10 工作日志

- **ADR-025: Redis 查询体验对齐 RDM（Redis Desktop Manager）设计完成：** 用户提出"Redis 的查询需要参考一下 redis desktop manager"。调研：原版 RDM 已商业化，社区默认指开源分支 Another Redis Desktop Manager（qishibo/AnotherRedisDesktopManager），其核心生产力模型为 key-list 面板（type/TTL/size 列 + 过滤 + 增量加载）、命名空间树（`:` 折叠成文件夹）、类型感知值查看器（string/hash/list/set/zset/stream + JSON 自动格式化）、CLI 控制台（历史/提示/dump）、内存分析/Pub-Sub/Monitor。ChatQuery Redis 现状：命令编辑器 + Tree db→key 惰性展开 + `browse_key` 按类型读值但拍平成 `RedisResult.lines: Vec<String>` 丢失结构语义、无 key-list 面板/命名空间/值编辑。设计决策遵循 ADR-022「借模式不借像素」：分 Phase A/B/C 兑现。Phase A（首推）：A1 类型感知值查看器（`RedisResult` 加可选 `value: Option<RedisValueView>`，`browse_key` 填充结构化 entries，前端按 type 分发专用组件，通用命令 `value=None` 回退 lines 向后兼容）；A2 key-list 面板（新增 `list_keys_meta` 命令，复用 SCAN + **强制 `redis::pipe()` pipeline** 批量 TYPE+TTL+MEMORY USAGE 避免 N×3 往返放大，前端 Redis db 节点选中时中心区切为 key-list｜value viewer 浏览器模式）；A3 控制台增强（复用 queries 表加 db_type 标记 + 命令补全 + dump 导出）。Phase B：命名空间树（`:` 折叠）+ 值写回（兑现 ADR-018/019 推迟）。Phase C：显式放弃内存分析/Pub-Sub/Monitor/binary viewer/Cluster 等重功能。产出：`adr-025-redis-query-rdm-style.md`（Status: Proposed）+ 两张架构图（体验对比 + 数据流）。纯增量、可逆、不改动 MySQL 路径/连接模型/LLM 工具。
