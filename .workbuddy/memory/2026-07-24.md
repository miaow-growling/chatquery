### 明确放弃（后续独立 Phase）

### 关键设计点（复用价值高）

## Phase 17 — SQL 格式化 + 表关系视图（ADR-021）

### 背景
对照 Chat2DB（OtterMind/Chat2DB，4071 次提交的成熟 AI DB 客户端）发现两个缺失：SQL 格式化（所有 DB 工具标配）和表关系/ER 视图。

### 实现
- **SQL 格式化**（纯前端）：引入 `sql-formatter` npm 包。`editor.ts` 的 `EditorHandle` 加 `formatSql()` — 有选区时只格式化选区，否则格式化全文。语言固定 mysql，关键字大写，缩进 2 空格。`App.tsx` 编辑器工具栏加"格式化"按钮。
- **表关系视图**（前后端）：
  - `src/db/mysql.rs`：新增 `ForeignKeyInfo` 结构体 + `list_relationships(cfg, db)` 查 `INFORMATION_SCHEMA.KEY_COLUMN_USAGE WHERE REFERENCED_TABLE_NAME IS NOT NULL`。
  - `src-tauri/src/commands.rs`：新增 `list_relationships` 命令；`main.rs` 注册。
  - `frontend/src/types.ts`：加 `ForeignKeyInfo` 接口。
  - `frontend/src/api.ts`：加 `listRelationships` 方法。
  - `frontend/src/App.tsx`：加 `relationshipView` 状态 + `renderRelationships()` + `showRelationships()`。结果面板支持三种视图：数据/表结构/表关系。`Tree.tsx` db 节点右键加"表关系"菜单项。
- `cargo check` ✅；`cargo test --lib` 16/16 ✅；`npm run build` 145 模块零错 ✅。

### 关键设计点
- SQL 格式化器 `formatSql()` catch 异常后静默失败（返回 false），不破坏编辑器内容。对存储过程/DELIMITER 等非标准语法可能不出效果但不报错。
- 表关系视图是列表形式而非图形化 ER 图——Constraint | 子表 | 子列 | → | 父表 | 父列。列表对查看足够，图形化留给后续可选增强。
- 两个功能完全正交，互不依赖。`relationshipView` 和 `structureView` 都是 transient state，由 `clearEditState()` 统一清空。
