# ChatQuery 端到端自测清单

单测（38 passed）只保证**逻辑正确**，保证不了**集成对齐**——事件名拼错、命令没注册、
Tauri 序列化字段名不匹配，这些编译器和单测都抓不到，只有真跑一遍才暴露。
本清单覆盖三块新能力：知识库（ADR-AI-6）、写审计（ADR-AI-1 决策3）、
超时 + token 用量（ADR-AI-4 决策2/3）。

## 0. 前置

```bash
# 后端（Rust 改动必须重启，HMR 不管 Rust）
cargo run --manifest-path src-tauri/Cargo.toml --no-default-features
# 前端 dev（前端改动 HMR 生效，窗口内 Cmd+R 刷新）
cd frontend && npm run dev
```

要求：
- 至少一个可连的 MySQL 连接，库里有几张表。
- LLM 已配置（设置 ⚙ 里能看到"LLM 已配置"）。
- **注意**：新增的 Tauri 命令（`list_audit_logs`）必须重启 cargo 才注册，
  否则前端报 `Command list_audit_logs not found`。这是踩过的坑。

## 1. 知识库（ADR-AI-6）

| # | 步骤 | 预期 |
|---|------|------|
| 1.1 | ⚙ → 知识库 tab → 新建知识库 | 立刻出现空白文档编辑区（不是无反应）|
| 1.2 | 填名称 + 内容，勾选一个连接/库绑定，点"保存文档" | 一次点击同时保存内容与绑定；列表出现该文档 |
| 1.3 | 重新打开设置 → 知识库 | 内容和绑定都还在（落盘成功）|
| 1.4 | 编辑内容后保存，再打开 | 显示新内容，没有产生重复文档 |
| 1.5 | 删除文档 | 列表消失；重开设置仍不在 |

### 1.6 注入验证（核心，必须真发一次对话）

先造一条**模型不可能猜到**的知识，例如：

```
本库 orders 表的 status 字段：7 = 已风控拦截（内部约定，不在注释里）
```

绑定到当前连接的当前库，然后在 Chat 里问：

> orders 表 status=7 是什么意思？

- ✅ **通过**：回答里出现"风控拦截"。说明 `context_block` 被动注入生效。
- ❌ **失败**：模型说"不清楚 / 需要看表注释"。检查绑定是否指向当前选中的库
  （绑定粒度是连接 + 库，选错库不会注入）。

再验证主动检索通道：问一个知识库里有、但上下文块可能被截断的内容，
观察工具气泡里是否出现 `SearchKnowledge` 调用。

## 2. 写操作审计日志（ADR-AI-1 决策3）

审计只记**写路径**，只读查询不留痕——先建立这个预期，否则会误判成"没记录"。

| # | 触发方式 | 期望判定 | 期望行为 |
|---|---------|---------|---------|
| 2.1 | 让 AI 执行 `SELECT ...` | 无记录 | 审计列表不新增 |
| 2.2 | 让 AI 执行 `UPDATE ... WHERE id=1`，弹窗点**执行** | `write-approved` | SQL 真跑，审计出现橙色"已批准" |
| 2.3 | 同上，弹窗点**拒绝** | `write-rejected` | SQL 不跑，AI 收到"用户拒绝，不要重试"并停手（不该换个写法再试）|
| 2.4 | 弹窗出现后**什么都不点，等 5 分钟** | `write-expired` | 300s 超时自动放弃，界面不卡死 |
| 2.5 | 让 AI 执行 `DROP TABLE xxx` | `deny` | **不弹窗**、不触库，直接红色"已阻断" |

打开方式：Chat 面板标题栏 🛡 按钮。

检查每条记录含：判定标签、连接名、库名、SQL 全文、时间。
时间应是本地时区可读格式，不是裸时间戳。

**边界**：2.4 需要真等 5 分钟，嫌慢可临时把 `session.rs` 的确认超时调小验证，
验完改回——但别忘了改回。

## 3. 单 turn 总超时（ADR-AI-4 决策2）

`TURN_TIMEOUT = 300s`，正常对话碰不到，需要人为制造慢场景：

| # | 步骤 | 预期 |
|---|------|------|
| 3.1 | 正常问一句 | 秒回，不受影响 |
| 3.2 | 临时把 `TURN_TIMEOUT` 改成 `10s` 重启，问一个复杂多步问题（触发规划 + 多 worker）| 10 秒后出现 `⏱ 超出时间上限`，输入框恢复可用，"停止"变回"发送" |
| 3.3 | 超时后立刻再发一条 | 正常工作，没有残留状态污染 |

关键观察点：**超时后 `streaming` 必须落回 false**。这是最容易漏的——
后端 timeout 了但没补发 `ChatDone`，前端就永远转圈。

## 4. Token 用量（ADR-AI-4 决策3）

| # | 步骤 | 预期 |
|---|------|------|
| 4.1 | 发一句简单问题 | 输入框上方出现 `⚡ 本轮 N tokens（入 X / 出 Y）· 会话累计 N` |
| 4.2 | 再发一句 | 本轮数字刷新，累计**递增**（不是被覆盖）|
| 4.3 | 发一个复杂问题（触发 plan + 多 worker + synthesize）| 本轮数字明显更大——它包含了规划、每个 worker、综合的所有调用 |
| 4.4 | 切到 Anthropic 厂商再发 | 同样有数字（走的是 `message_start` + `message_delta` 累加路径）|
| 4.5 | 若某厂商不上报 usage | 显示"本轮用量未上报"，而不是 `0 tokens` |

4.5 是刻意设计：**未知 ≠ 零**。显示 0 会让人以为这轮免费。

## 附：失败时先看哪里

| 症状 | 大概率原因 |
|------|-----------|
| `Command xxx not found` | Rust 命令改了但没重启 cargo |
| 前端完全没反应、无报错 | 用了 `window.prompt/confirm/alert`——Tauri v2 webview 不实现，静默失效 |
| `mismatched types ... SQL type BINARY` | 新增的 INFORMATION_SCHEMA 查询漏了 `CAST(col AS CHAR)` |
| 窗口瞬间消失 | WKWebView 原生崩溃，不是 JS 错误——查 sticky-left / backdrop-filter |
| 事件收不到 | `commands.rs` 桥接 match 有 `_ => {}` 兜底，新变体没加 arm 会被静默吞掉 |
